1. AJAX: actualizăm o parte din pagină

AJAX vine de la Asynchronous JavaScript and XML. Este o tehnică: JavaScript comunică asincron cu serverul, primește date și modifică interfața fără să reîncarce întregul document.

Litera X a rămas în nume, dar putem folosi JSON, text sau alte formate. În această lecție folosim JSON.

  1. Utilizatorul apasă „Vezi orele”.
  2. JavaScript cere programul filmului.
  3. Serverul răspunde cu datele.
  4. JavaScript afișează orele într-un panou. Restul paginii rămâne pe loc.

API-ul stabilește ce cerem și ce primim. AJAX descrie felul în care actualizăm pagina. Promise reprezintă un rezultat care poate deveni disponibil mai târziu.

O aplicație poate combina navigarea între pagini cu actualizări AJAX. Nu trebuie ca toate cererile ei să întoarcă exclusiv JSON.

Detalii: MDN: cereri de rețea din JavaScript.

2. Asincron: pornim o operație și continuăm

Codul sincron rulează în ordine. Când programăm un timer sau pornim o cerere de rețea, nu trebuie să ocupăm firul principal așteptând rezultatul.

console.log("1. Comandăm popcorn.");

setTimeout(() => {
  console.log("3. Popcornul este gata.");
}, 1000);

console.log("2. Alegem un film între timp.");
// Ordine: 1, 2, apoi 3, după aproximativ o secundă.

Funcția trimisă lui setTimeout este un callback: o funcție transmisă altei funcții pentru a fi apelată de aceasta. Aici este apelată mai târziu.

Un callback nu este automat asincron. În [10, 20].map(pret => pret * 2), callbackul rulează în timpul apelului map. O funcție care primește sau întoarce funcții este numită higher-order function.

Rezultatul nu apare mai repede doar pentru că îl citim

let mesaj = "Se pregătește…";

setTimeout(() => {
  mesaj = "Gata!";
  console.log(mesaj); // "Gata!", mai târziu.
}, 1000);

console.log(mesaj); // "Se pregătește…", imediat.

Folosim rezultatul când operația este gata: în callback, într-un then sau după await.

Ce întoarce setTimeout? 
const timerId = setTimeout(() => {
  return "Gata!";
}, 1000);

console.log(typeof timerId); // "number" în browser.
clearTimeout(timerId);       // Anulăm timerul.

În browser, setTimeout() întoarce un identificator al timerului. Nu întoarce rezultatul callbackului. return "Gata!" ar ieși doar din callback.

3. Event loop: cine primește rândul?

Pentru codul de pe firul principal, JavaScript execută câte o bucată de cod odată. Call stack ține evidența apelurilor în curs. Browserul gestionează operații precum timerele și rețeaua, iar callbackurile sunt programate pentru execuție.

Când codul curent se termină, callbackurile promisiunilor pregătite rulează ca microtaskuri, înaintea următorului task, cum ar fi un callback de timer pregătit.

console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A, D, C, B

Promise.resolve() creează aici o promisiune deja îndeplinită. Callbackul din then tot nu rulează imediat. Nici un timer cu 0 nu întrerupe codul curent.

Cine ajunge primul?

Prezice ordinea celor patru litere, apoi rulează exemplul. Lista este completată de callbackurile reale.

    Rezultatul va apărea aici.

    Asincron nu înseamnă că orice cod este executat în paralel sau că pagina nu se poate bloca. Un calcul foarte lung pe firul principal poate întârzia atât interfața, cât și callbackurile. Timpul dat unui timer nu este o garanție a momentului exact de execuție.

    Detalii opționale: MDN: taskuri și microtaskuri.

    4. Promise: bonul unei comenzi care se pregătește

    O promisiune este un obiect care reprezintă finalizarea unei operații. Nu este rezultatul însuși și nu garantează succesul.

    • pending: încă așteptăm.
    • fulfilled: operația a reușit și avem o valoare.
    • rejected: operația a eșuat și avem un motiv.

    După succes sau eșec, promisiunea este settled și nu își mai schimbă starea. O încercare nouă poate crea o promisiune nouă.

    Creăm o promisiune pentru o comandă simulată

    function preparaPopcorn(disponibil) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (disponibil) {
        resolve("Popcornul este gata!");
      } else {
        reject(new Error("Nu mai avem porumb. Alege altă gustare."));
      }
    }, 1800);
  });
}

    Funcția transmisă lui new Promise rulează imediat și programează timerul. Timerul produce întârzierea. resolve(mesaj) livrează textul, iar reject(new Error(...)) semnalează eșecul.

    Folosim promisiunea: then, catch și finally

    Rulează acest bloc după definiția lui preparaPopcorn.

    preparaPopcorn(true)
  .then((mesaj) => {
    console.log(mesaj); // "Popcornul este gata!"
  })
  .catch((eroare) => {
    console.log(eroare.message);
  })
  .finally(() => {
    console.log("Putem prelua altă comandă.");
  });
    • then primește valoarea de succes.
    • catch primește eroarea din lanț.
    • finally face curățenia comună, de exemplu reactivează un buton. Nu primește rezultatul ca argument.

    5. Un lanț: rezultatul unui pas devine intrarea următorului

    Fiecare apel then() întoarce o promisiune nouă. Ce returnăm din callback determină rezultatul următorului pas.

    Promise.resolve(20)
  .then((pret) => {
    return pret * 2;
  })
  .then((total) => {
    return `Două bilete costă ${total} lei.`;
  })
  .then((mesaj) => {
    console.log(mesaj); // "Două bilete costă 40 lei."
  });
    • Returnăm o valoare: următorul then o primește.
    • Returnăm o promisiune: lanțul așteaptă rezultatul ei.
    • Aruncăm o eroare: lanțul trece către un handler de eroare, de exemplu catch.

    Capcana: return uitat

    Promise.resolve(20)
  .then((pret) => {
    pret * 2; // Calculăm, dar nu returnăm.
  })
  .then((total) => {
    console.log(total); // undefined
  });

    Dacă pornești o altă operație asincronă în then, returnează-i promisiunea ca pasul următor să o aștepte. Vom aplica asta când cerem întâi filmele și apoi programul.

    Opțional: după catch, lanțul poate continua 
    Promise.reject(new Error("Catalog indisponibil"))
  .catch(() => {
    return []; // Alegem o valoare de rezervă.
  })
  .then((filme) => {
    console.log(filme.length); // 0
  });

    Dacă un catch se termină normal, eroarea este tratată. Poți arunca din nou eroarea dacă vrei să rămână un eșec. O listă goală de rezervă nu este întotdeauna potrivită; uneori utilizatorul trebuie să vadă mesajul de eroare.

    Promisiunile folosesc tot callbackuri. Avantajul este că putem lega operațiile într-un lanț și putem trata erorile într-un loc, fără multe funcții imbricate, numite uneori callback hell.

    Detalii: MDN: folosirea promisiunilor.

    6. JSON este text; obiectul JavaScript este o valoare în memorie

    const rezervare = { filmId: 1, loc: "A2" };
const text = JSON.stringify(rezervare);

console.log(text);        // '{"filmId":1,"loc":"A2"}'
console.log(typeof text); // "string"

const copie = JSON.parse(text);
console.log(copie.loc);   // "A2"

    JSON.stringify() serializează datele în text JSON. JSON.parse() face transformarea inversă. JSON acceptă obiecte, liste, texte, numere, booleeni și null, dar nu funcții sau comentarii.

    Nu orice text este JSON valid. De exemplu, o pagină HTML de eroare nu poate fi citită cu json(). Cheile unui obiect JSON au ghilimele duble; valorile pot fi și numere, liste sau alte tipuri acceptate.

    7. Fetch: două așteptări, un rezultat

    Prima promisiune oferă un Response: status, headere și acces la corp. raspuns.json() întoarce o altă promisiune, care oferă datele citite și parsate.

    Pregătire: pornim serverul local

    Deschide proiectul prin serverul local folosit la curs, de exemplu Live Server. Alternativ, dacă ai Python, rulează din folderul principal al proiectului:

    python3 -m http.server 8000 --bind 127.0.0.1 --directory html

    Apoi deschide http://localhost:8000/AJAX-Promises.html. Oprești serverul cu Ctrl + C. Deschiderea prin file:// nu este potrivită pentru cererile locale fetch.

    GET: cerem catalogul

    fetch("exemple-ajax/filme.json")
  .then((raspuns) => {
    if (!raspuns.ok) {
      throw new Error(`HTTP ${raspuns.status}`);
    }
    return raspuns.json(); // Returnăm promisiunea citirii corpului.
  })
  .then((filme) => {
    console.log(filme[0].titlu); // "Drum spre Marte"
  })
  .catch((eroare) => {
    console.log(`Nu am putut citi filmele: ${eroare.message}`);
  });

    ok este true pentru statusuri de la 200 la 299. Un status 404 sau 500 nu respinge automat promisiunea fetch; noi verificăm răspunsul și aruncăm eroarea. O problemă de rețea poate respinge fetch înainte să existe un Response.

    Extragem partea reutilizabilă în ajax-api.js

    function citesteJSON(url) {
  return fetch(url).then((raspuns) => {
    if (!raspuns.ok) {
      throw new Error(`HTTP ${raspuns.status}: resursa nu a putut fi citită.`);
    }
    return raspuns.json();
  });
}

    Funcția nu afișează nimic și nu ascunde erorile. Codul interfeței decide ce să facă prin then și catch.

    <script src="ajax-api.js" defer></script>
<script src="ajax-promises.js" defer></script>

    Scripturile externe clasice cu defer sunt executate în ordinea lor din document. Astfel, funcția de citire există înainte să o folosească demonstrațiile.

    De recunoscut: XMLHttpRequest, jQuery și Axios

    XMLHttpRequest este o altă interfață a browserului pentru cereri. Nu întoarce nativ un Promise; de obicei lucrăm cu evenimentele sale. Acest exemplu citește același catalog:

    8. Atelier: alegem filmul, apoi încărcăm orele

    Catalogul și programul sunt fișiere JSON servite prin HTTP. Ilustrează citirea datelor unui API; nu fac rezervări și nu au o bază de date.

    Ce vedem în seara asta?

    Trei filme imaginare, fiecare cu propriul program. Încarcă lista, filtrează după gen și descoperă orele la click.

    Catalogul așteaptă prima cerere.

      Programul filmului

        Filtrarea după gen se face în browser, pe lista deja primită. „Vezi orele” trimite o cerere nouă. Butonul 404 cere intenționat un fișier absent; poți reveni cu „Încarcă filmele”.

        Pasul 1: știm forma datelor

        Un film din catalog conține ID-ul, titlul, genul, durata, un simbol și descrierea. Pentru filmul 1, programul arată astfel:

        { "filmId": 1, "sala": "Sala Orion", "ore": ["17:00", "19:30", "21:45"] }

        Pasul 2: legăm două citiri care depind una de alta

        Acest exemplu pentru consolă folosește citesteJSON de mai sus. Cere catalogul, apoi programul primului film.

        citesteJSON("exemple-ajax/filme.json")
  .then((filme) => {
    if (filme.length === 0) {
      throw new Error("Catalogul este gol.");
    }
    const primulFilm = filme[0];
    return citesteJSON(`exemple-ajax/program-${primulFilm.id}.json`);
  })
  .then((program) => {
    console.log(program.sala);           // "Sala Orion"
    console.log(program.ore.join(", ")); // "17:00, 19:30, 21:45"
  })
  .catch((eroare) => {
    console.log(eroare.message);
  });

        Al doilea then primește programul, fiindcă primul returnează promisiunea celei de-a doua citiri. Nu avem nevoie de un then imbricat în alt then.

        Pasul 3: în interfață, utilizatorul alege momentul celei de-a doua cereri

        În demo afișăm întâi cardurile. Butonul fiecărui card apelează incarcaProgram(film), care folosește ID-ul acelui film.

        Vezi funcția care încarcă și afișează orele

        Acesta este codul folosit de demo. Variabilele DOM sunt definite în scriptul interfeței. seteazaIncarcare dezactivează sau reactivează controalele catalogului.

        function incarcaProgram(film) {
  seteazaIncarcare(true);
  programPanou.hidden = false;
  programTitlu.textContent = film.titlu;
  programStare.textContent = "Se încarcă programul…";
  oreLista.replaceChildren();

  return citesteJSON(`exemple-ajax/program-${film.id}.json`)
    .then((program) => {
      if (!Array.isArray(program.ore)) {
        throw new Error("Programul trebuie să conțină o listă de ore.");
      }
      for (const ora of program.ore) {
        const element = document.createElement("li");
        element.textContent = ora;
        oreLista.append(element);
      }
      programStare.textContent = program.ore.length === 0
        ? "Nu sunt proiecții programate pentru acest film."
        : `${program.sala}: ${program.ore.length} proiecții. Program demonstrativ.`;
    })
    .catch((eroare) => {
      programStare.textContent = `Nu am putut încărca orele. ${eroare.message} Apasă din nou «Vezi orele» pentru a reîncerca.`;
    })
    .finally(() => seteazaIncarcare(false));
}

        Pasul 4: verificăm și când lucrurile nu merg

        • Loading: arătăm un mesaj și dezactivăm controalele care ar porni cereri concurente.
        • Succes: construim elementele cu createElement și punem textele cu textContent.
        • Gol: explicăm de ce nu apar filme sau ore.
        • Eroare: afișăm un mesaj și oferim reîncercare. Nu păstrăm orele filmului anterior sub alt titlu.

        În Network vei vedea întâi filme.json, apoi, la click, program-1.json sau programul altui film. Contorul de lângă automatul de popcorn își păstrează valoarea: documentul nu a fost reîncărcat.

        Opțional: Promise.all pentru două cereri independente

        Când știm deja cele două adrese, putem porni ambele citiri și aștepta rezultatele împreună. Exemplul refolosește citesteJSON.

        Promise.all([
  citesteJSON("exemple-ajax/program-1.json"),
  citesteJSON("exemple-ajax/program-2.json")
])
  .then((programe) => {
    console.log(programe[0].sala); // "Sala Orion"
    console.log(programe[1].sala); // "Sala Luna"
  })
  .catch((eroare) => console.log(eroare.message));

        Rezultatele păstrează ordinea din lista de intrare, chiar dacă a doua cerere termină prima. Dacă una eșuează, promisiunea comună este respinsă; celelalte cereri nu sunt anulate automat.

        9. Când trimitem date: POST, PUT și DELETE

        Până acum am citit date. Pentru a trimite JSON, alegem metoda, descriem formatul cu Content-Type și serializăm obiectul în body.

        Funcția de mai jos este un model pentru un API care primește JSON și întoarce JSON sau 204. Definirea ei nu trimite nicio cerere.

        function trimiteJSON(url, metoda, date) {
  return fetch(url, {
    method: metoda,
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(date)
  }).then((raspuns) => {
    if (!raspuns.ok) {
      throw new Error(`HTTP ${raspuns.status}`);
    }
    if (raspuns.status === 204) {
      return null; // Succes, fără corp de citit.
    }
    return raspuns.json();
  });
}

        10. Aceeași idee, scrisă cu async / await

        Nu schimbăm modul în care funcționează rețeaua. Schimbăm forma codului care consumă promisiunile. Acest exemplu refolosește citesteJSON.

        async function arataPrimulProgram() {
  try {
    const filme = await citesteJSON("exemple-ajax/filme.json");
    if (filme.length === 0) {
      throw new Error("Catalogul este gol.");
    }
    const program = await citesteJSON(`exemple-ajax/program-${filme[0].id}.json`);
    console.log(program.ore.join(", "));
  } catch (eroare) {
    console.log(eroare.message);
  }
}

arataPrimulProgram(); // Mai târziu: "17:00, 19:30, 21:45"

        await suspendă continuarea funcției async până la rezultat; nu oprește întreaga pagină. Funcția async întoarce la rândul ei o promisiune.

        Folosește forma pe care o urmărești mai ușor. Pentru început, păstrează un flux consecvent: fie then / catch, fie await cu try / catch.

        11. Cinci greșeli pe care acum le poți recunoaște

        1. Citesc prea devreme rezultatul. Îl folosesc în callback, then sau după await.
        2. Uit return într-un then. Următorul pas poate primi undefined sau poate continua fără operația pornită.
        3. Cred că fetch respinge automat un 404. Verific raspuns.ok.
        4. Citesc JSON din orice răspuns. Un 204 nu are corp; un răspuns HTML nu este JSON.
        5. Dezactivez butonul și îl uit blocat după eroare. Îl reactivez în finally.

        Fișierele lecției: citirea JSON, codul demonstrațiilor, stilurile demonstrațiilor și catalogul.

        Temă simplă: automatul de limonadă

        Creează o pagină cu un select pentru „Avem lămâi” / „Nu mai avem lămâi”, un buton „Prepară” și un paragraf pentru rezultat.

        1. Scrie preparaLimonada(disponibil), care întoarce un Promise.
        2. După aproximativ o secundă, rezolvă promisiunea cu „Limonada este gata!” sau respinge-o cu un obiect Error.
        3. La click, citește opțiunea, afișează „Se prepară…” și dezactivează butonul și selectul.
        4. Folosește then pentru succes, catch pentru eroare și finally pentru a reactiva controalele.

        Verificare: testează succes, apoi eșec, apoi din nou succes. Mesajul se schimbă la fiecare comandă, controalele sunt reactivate în ambele cazuri, iar pagina nu se reîncarcă. Acest exercițiu nu are nevoie de server.

        Indiciu

        Pornește de la preparaPopcorn. Înlocuiește mesajele și întârzierea, apoi leagă funcția de elementele tale HTML. Nu încerca să returnezi băutura direct din callbackul setTimeout.

        Temă puțin mai complexă: meniu și ingrediente la click

        Creează o pagină mică, un meniu.json și câte un fișier de ingrediente pentru două produse. Deschide pagina prin serverul local.

        [
  { "id": 1, "nume": "Limonadă", "pret": 12 },
  { "id": 2, "nume": "Ciocolată caldă", "pret": 15 }
]

        Pentru ingrediente-1.json, poți folosi { "ingrediente": ["apă", "lămâie", "miere"] }. Creează și al doilea fișier cu ingredientele alese de tine.

        1. Reutilizează funcția citesteJSON într-un fișier separat, încărcat înaintea scriptului interfeței.
        2. La click pe „Încarcă meniul”, cere lista și afișează numele și prețul fiecărui produs.
        3. Fiecare produs are un buton „Ingrediente”, care cere fișierul corespunzător ID-ului și afișează ingredientele.
        4. Adaugă mesaje de încărcare, eroare și rezultat gol. Golește rezultatul precedent înainte de o nouă cerere.
        5. Dezactivează controalele care ar putea porni cereri suprapuse și reactivează-le în finally.
        6. Testează o adresă greșită, apoi repar-o și încearcă din nou.

        Verificare: apar două produse, fără dubluri după reîncărcare. Ingredientele sunt cerute abia la click. Un fișier lipsă afișează o eroare, nu ingredientele produsului precedent. După eroare, poți reîncerca.

        Indiciu

        Adresa poate fi construită cu `ingrediente-${produs.id}.json`. Urmărește în Network momentul în care apare fiecare cerere. Pentru această temă sunt suficiente două produse și câteva ingrediente.
